## Strongest ReSpace applications — proposals

1. **Choose three visible problems that the real app can answer, then close those exact loops.** For example: an object the user wants to keep; an awkward empty spot; and a budget that constrains the design. Show those conditions first, then show the corresponding real input and proposed result. These should be selected against the working build before scripting. Do not create three entertaining problems that the eventual demo cannot solve.
2. **Let a human need motivate the product reveal.** A character deciding how to accommodate a new routine can lead naturally to a scan and intent selection. The app appears because a decision is needed, rather than because the narrator announces a startup midway through an unrelated manifesto.
3. **Return to the original room and behavior for the payoff.** If the opening shows someone unable to use a corner, show the same person using that corner at the end. If only a proposed layout is available, present it clearly as a proposed design; a staged physical after-shot can be separate.

**Small-team feasibility:** the structure transfers easily to one room, a few recurring compositions, real app inserts and careful sound design. A personified piece of furniture is a possible creative direction, but it adds prop, performance and tonal demands; copying the wearable-keyboard gag is unnecessary. The raw model suggested live AR overlays, dimensional warning pills and an instantly reorganizing room. Those are not adopted as ReSpace feature demonstrations unless the build actually supports them.

**What not to copy:** the therapy premise, exact character behavior, claim of instantaneous processing, or a long problem section simply because it worked for this narrative. This film establishes its comic contract early; a serious spatial-personality opening needs its own equally clear reason to keep watching.
