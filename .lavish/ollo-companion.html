At home, then beside the conversation.

On My Rooms, Ollo offers a compact welcome. In a Room, the current question or actual status becomes Ollo’s dialogue just above the existing text box.

Still until you replay a gesture.

  • Small and anchored.About 80 pt tall on My Rooms, 64 pt beside the composer. Keep the same reserved space in every pose. On the design canvas, idle Ollo can remain without a bubble.
  • One useful message.Reuse the existing question or status. A short explanation can replace helper copy on scan setup; the primary action stays obvious. Let essential text wrap.
  • Move once, then settle.A welcome wave once per app session. A quiet pose change for a new question. A small hop only for a newly committed successful design.

While the keyboard is open or a long question needs space, shrink Ollo to 40 pt or hide the image first. Keep the text, selection context and Send control visible.

Small SwiftUI implementation

Three contained steps.

1. Bundle the poses

Add the nine PNGs to asset catalogs. Preserve a shared canvas and rendering size, with alpha intact. Make size-appropriate runtime copies so the app does not decode oversized masters for a 64 pt character.

2. Add one Ollo view

One OlloView.swift with the pose names, an image, an optional message and a short cancellable frame sequence. Fixed image slot; naturally wrapping text. Reuse ReSpace typography and surfaces.

3. Attach at existing points

ContentView for welcome; RoomRequestBar for the question above the input; OperationPanel for focused questions/status; DesignView for composer parity. No changes to submission or planning logic.

When Ollo changes pose
  • Home: idle → wave A → wave B → wave A → idle. Play once per session, not on each return.
  • New question: asking briefly, then listening. Trigger only when the operation/question/revision identity changes, never on a poll refresh.
  • Input focus: listening and still. Do not animate on each keystroke or every placeholder change.
  • Actual queued/running operation: one transition to thinking, then hold. Keep truthful existing progress and cancellation actions.
  • New committed success: idle → crouch → hop → idle once. No celebration for a failed, cancelled, rejected, partial-success or fit-pending result.
  • Explanation: presenting and still; e.g. scan setup’s existing guidance. Errors keep the existing readable notice and recovery action.
Keep it quiet and reliable
  • One Ollo on the visible screen. No idle loops, sound, automatic haptics, floating overlays, streaks, typing theatrics or a new chat route.
  • The mascot image never intercepts taps, drags or room-camera gestures. Existing question/details controls keep their current actions.
  • The default idle pose is the fallback for unknown states. A missing sprite hides the image and leaves the text/action intact.
  • Respect Reduce Motion with a static appropriate pose. Pause when the app is inactive, cancel a sequence when the view/state changes, and replace an interrupted sequence rather than queueing gestures.
  • Text remains accessible; hide the decorative character from VoiceOver. Do not announce every frame or steal keyboard focus.
  • Keep presentation state local. Ollo never sends a request, approves a budget, changes a draft, edits a scene, or decides whether an operation succeeded.
Verification before adding it to the app
  • Check every PNG for real alpha, clear canvas edges, consistent character identity and stable frame alignment. Inspect the sprites on white, lavender and dark backgrounds.
  • Preview My Rooms, the question composer and focused question flow on a small iPhone, with long questions, maximum text size, keyboard visible and Reduce Motion enabled.
  • Poll refresh and navigation must not restart a gesture. A changed question must play only once. An interrupted animation must leave no running task behind.
  • Verify request submission, draft preservation, answer revision, budgeting, scene gestures, Send and Cancel behave identically with Ollo visible.
  • Inspect a fresh committed success, partial edit, failure, unknown response, cancellation and plan-only result so celebrations never imply an unconfirmed saved design.
