# Segmented walkthrough implementation status

Updated October 17, 2026. Branch: `scan-pipeline-redo`. No work on `main`. Gemini remains deferred.

The finished-room reconstruction path is now implemented and connected to the iOS viewer. This is a software implementation milestone, not a claim that arbitrary real rooms, every hidden furniture surface, the $5 total cloud cost, or minimum-phone frame rate have passed validation.

## Implemented

- Default `RESPACE_PIPELINE=walkthrough`: immutable capture verification → grounded discovery/SAM masks → multi-view identity reconciliation → captured-mesh ownership → object completion → clean photo-textured room surfaces → versioned scene graph/navigation → atomic final publication.
- Actual captured geometry and photo pixels remain authoritative. Simple occlusion boundaries close without replacing measured vertices/faces. Geometry must be watertight and avoid self-intersections/observed free space. More complex gaps use a configured foreground completion-worker contract with metric shape validation; no box/catalog substitution.
- Independent posters/paintings/boards retain captured pixels, wall support and source identities. Planar rugs use floor support. Coplanar decor regions are removed from the wall/floor texture bake before boundary-conditioned texture continuation. The native product has no estimate labels.
- Complete measured room polygons preserve openings. Source depth and object masks reject foreground texture contamination. Hidden wall/floor/ceiling textures use harmonic continuation from captured boundary colors, not a trained generative inpainting model.
- `SceneBundle` v2 owns object assets, transforms, materials, support regions/holes, navigation obstacles and internal provenance. Fixed structure/built-ins cannot become movable. Material runs are grouped before native import.
- `.building` revisions remain unpublished until all graph/dependency/hash/budget checks pass. Retried failures cannot expose a stale v2 scene. Repeating an already committed revision revalidates/reuses it rather than redoing reconstruction.
- The client verifies downloads and cached assets, scene identity/revision, dependencies, navigation and quality readiness before loading Model I/O assets into SceneKit.
- Native first-person look/walk controls have floor, wall, static-detail and object collision checks with substeps. Tap to select actual assets; move/rotate/remove furniture, move wall decor on its support, or change owned paint/tile/wallpaper finishes. Local changes save/reopen per reconstruction revision; Undo/Restore retain original assets.
- The new room screen shows processing progress and then the finished walkthrough. It does not expose the legacy partial model inspector. Operational errors and scan-quality errors remain distinct.
- Optional completion commands receive durable $5 per-capture reservations, return fingerprinted cost receipts, reuse checksummed results and cannot automatically repeat unknown billing outcomes. This is a completion-adapter budget, not proof of total VM/storage/network cost. A service timeout terminates the worker process group.
- Local and Linux bootstrap scripts install pinned public detection/segmentation dependencies. Nothing was deployed or started in Google Cloud as part of the branch work.

Implementation: `services/reconstruction/respace_reconstruction/walkthrough.py`, `surfaces.py`, `inventory.py`, `object_completion.py`, `budget.py`, `navigation.py`; `ReSpace/Domain/WalkthroughModels.swift`, `ReSpace/Rendering/WalkthroughView.swift`, reconstruction client and saved-room screen.

## Validation evidence

Python tests exercise an analytic room captured through real Open3D ray casting: calibrated RGB-D frames, measured shell/mesh and isolated furniture. The finished output contains a closed captured object, complete wall/floor/ceiling surfaces and a separate source-pixel poster. A regression checks that the poster texture keeps its pixels while the wall texture behind it is clean. Tests also cover opening-safe triangulation, completion receipts/caching, surface/asset integrity, failed revision exposure and static-mesh navigation.

The checked-in native fixture is generated by that Python pipeline and contains synthetic data only. Swift tests load its OBJ/MTL/textures through Apple's actual Model I/O/SceneKit importer, verify meter-scale bounds and test collision movement, fixed-object rules, capture/revision binding and material ownership. The iOS Simulator build passes.

Latest verification: 67 Python tests passed (one live-service test skipped); the Swift suite executed 49 tests with one live-service test skipped and no failures; the iOS Simulator build succeeded. Native import checks verify each entity’s material ownership and decoded MDLTexture pixel data. Physical-device performance, visual fidelity and complete automatic inventory on a fresh real scan remain release checks.

Earlier research experiments are retained in ignored benchmarks: 296 real RGB-D/photo frames; 22 SAM masks over nine RoomPlan priors; Grounding DINO/SAM discovery from four views; reciprocal association of three storage groups. These exposed false semantics and incomplete ownership. They are not complete segmentation ground truth. TripoSR runtime smokes exported chair meshes but failed watertightness/self-intersection checks at resolutions 64 and 128; that model is not adopted for production completion.

## Required real-room validation and limitations

1. Upload the fresh LiDAR scan with its original mesh. The earlier retained scan still lacks its declared original `scene_mesh`; it cannot substitute for complete input validation.
2. Run the default automatic inventory on furnished rooms, repeated neighboring objects, thin structures, reflective surfaces and actual wall art. Confirm every movable item is isolated and built-ins stay fixed. Model scores alone do not establish this.
3. Inspect object reverse sides and newly revealed walls/floors after movement/removal. Test captured writing/artwork and material ownership across viewpoints. Rescan requests should identify missing capture evidence rather than hide infrastructure failures.
4. Benchmark a chosen GPU completion adapter if measured-boundary closure is insufficient. The generic execution/receipt/validation contract is implemented; a deployed Pixal3D, WorldSculpt or SAM 3D model is **not** bundled or claimed reproduced. No GPU worker has been provisioned. Original-mesh admission currently caps at 800K triangles; curved/sloped shells are unsupported by the planar builder.
5. Measure native iPhone loading, memory, frame rate and thermal behavior, plus the complete cloud cost including retries, VM, disk and network. The 30-minute target/$5 total ceiling remain pilot gates.
