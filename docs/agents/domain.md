# Domain documentation

This repository uses a single domain context.

## Before exploring

Read the root `CONTEXT.md` glossary and relevant decisions in `docs/adr/`.

If a file or directory is absent, proceed silently. Create glossary
entries and ADRs only when terms or consequential decisions are resolved;
do not create empty documents as setup placeholders.

## Vocabulary

Use the glossary's canonical terms in specifications, issues, code,
tests and explanations. Respect its discouraged synonyms.

When a needed concept is missing, distinguish a real domain gap from
an unnecessary new term before extending the glossary.

## Decisions

Surface conflicts with relevant ADRs explicitly. Identify the decision
and explain why reconsideration may be needed; do not silently override it.
