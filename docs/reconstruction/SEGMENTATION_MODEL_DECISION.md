# Segmentation and editable mesh decision

Primary-source review, October 17, 2026 (America/Los_Angeles). Scope: actual object/decor preservation and independently exportable room geometry; Gemini is deferred. No model installation, checkpoint download, inference, reconstruction, or code changes were performed for this note. Workspace code was read; the parent reports 296 calibrated RGB-D views, nine RoomPlan objects, and SAM 2.1 tiny being installed/downloaded. Those counts and runtime readiness were not independently measured here.

## Decision

**Use SAM 2.1 Hiera tiny now, with RoomPlan-seeded image prompts plus a separate discovery pass, then geometry-based 2D tracking and global multi-view association. Preserve and split the measured/refined mesh; do not generate a replacement room.** Implement the small association adapter in the existing NumPy/Open3D pipeline, drawing on CDIS's tracking/3D-consolidation design and MaskClustering's independent-view consensus. Keep a CPU baseline and explicitly benchmark optional MPS. This is the most practical implementation choice for the current Mac, not a benchmark claim that tiny beats larger models.

For the next externally evaluated scene-level baseline, choose **CDIS with cached SAM masks**. It has the most directly applicable public interface reviewed: posed RGB-D, a point cloud, fine superpoints and cached 2D label maps. Its published environment is Linux/NVIDIA, so importing it unchanged is not a supported shortcut for this Mac. Before copying its code, pin/review the actual license file and third-party components. A lightweight independent implementation of the documented geometry/tracking algorithm avoids importing an incompatible legacy runtime.

**Segmentation is not completion.** SAM 2/3 predict image masks; CDIS, Open3DIS, MaskClustering, SAI3D and Any3DIS associate existing scene points into instances. None of those outputs alone is a closed, textured, editable reconstruction of an unseen object back or the wall behind a sofa. Object extraction, surface repair/completion, clean background, texture assets and final export remain separate stages.

Accepted product constraints remain: preserve actual furniture and posters/paintings/whiteboard contents; fixed structure with finish edits; seamless completion with internal provenance; final product only; invalid models cause rescan, with no cleanup UI. Lighting/shadow cleanup is excluded. $5/room and 30 minutes are the accepted ceiling/target, not achieved results.

## Why tracking plus geometry, rather than nearest boxes

MaskClustering makes multi-view mask agreement explicit. SAI3D aggregates semantic mask evidence over superpoint affinities. Any3DIS instead emphasizes 3D-aware SAM 2 tracking and selecting consistent views because naive merging creates fragmented/redundant proposals. CDIS combines depth-warped short-term tracks with 3D merging and overlap/co-occurrence consolidation. These are relevant design ideas; simply back-projecting each rectangle or merging nearest detections by category is not an implementation of them. [MaskClustering paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Yan_MaskClustering_View_Consensus_based_Mask_Graph_Clustering_for_Open-Vocabulary_3D_CVPR_2024_paper.pdf), [SAI3D paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Yin_SAI3D_Segment_Any_Instance_in_3D_Scenes_CVPR_2024_paper.pdf), [Any3DIS paper](https://openaccess.thecvf.com/content/CVPR2025/papers/Nguyen_Any3DIS_Class-Agnostic_3D_Instance_Segmentation_by_2D_Mask_Tracking_CVPR_2025_paper.pdf)

The following is a **proposed ReSpace adapter**, not a claim that benchmark code or quality has already been reproduced:

1. **Preserve one metric scan frame.** Keep original ARKit mesh, source images/depth/confidence/poses and RoomPlan immutable. Use the existing `camera_to_cv_world` adapter; verify projection on known landmarks before trusting masks. Original RGB masks and lower-resolution depth are different grids. Resize categorical labels using nearest neighbor or project explicitly through calibration, and preserve unknown/boundary pixels. Do not use interpolated label IDs or resize a photograph without updating intrinsics.
2. **Seed the nine known objects, then discover more.** For each RoomPlan object select several sharp, geometrically useful views, project a loose box, and use visible interior positive points plus verified outside negative points. A box is a prompt, never the output mask. Run class-agnostic proposals or optional text detection on diverse views for objects RoomPlan missed. Nine seed objects are not the ground-truth inventory. Keep stable `unknown_object` instances if category naming is uncertain.
3. **Cache image embeddings.** Process all useful prompts for one RGB image after one `set_image`. Start with a bounded diverse-view subset, then add views where boundaries/coverage disagree; retain all 296 views as evidence. Avoid assuming every frame needs an expensive automatic 32×32 prompt-grid pass. Record per-stage inference time before choosing the subset size; no CPU/MPS throughput is established.
4. **Build depth-visible surface evidence.** Project original mesh samples or raycast calibrated views. Require positive camera depth, image bounds, frontmost z-buffer visibility and measured-depth agreement. Zero/confidence-rejected depth means unknown, not free space. If mesh-rendered depth fills a sensor hole, record it as mesh-derived evidence rather than an independent sensor observation. Use adaptive tolerances tied to residuals/confidence, not one room-wide distance that swallows thin structures.
5. **Track between overlapping views.** Back-project accepted mask pixels with depth, transform into the next or overlapping frame, z-buffer them, and match warped masks to current proposals by overlap plus geometry. Use one-to-one assignment with unmatched/new/occluded states; maintain a short recent-view queue. Geometric view overlap matters more than adjacent timestamps when the saved keyframes are sparse. SciPy supplies `linear_sum_assignment` for bounded bipartite matching; visibility and candidate costs remain ReSpace logic. [SciPy matching API](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html)
6. **Consolidate globally with constraints.** Represent each track by confident source-surface IDs/weights. Link tracks only with multi-view geometric support and compatible extents/supports. Two distinct masks visible as separate physical objects in the same view create a cannot-merge constraint. Do not merge identical chairs/posters because their category, color or texture matches; do not rely on transitive single-link clustering across touching objects. RoomPlan IDs are strong seeds but not hard boxes that claim every enclosed floor pixel. Leave contradictory evidence unresolved internally until further views resolve it or the quality gate requests rescan.
7. **Assign source faces without destroying geometry.** Use finer-than-object surface patches or samples, retaining original vertex/face correspondence and boundary uncertainty. A premerged superpoint spanning chair and floor cannot be split by later superpoint association. Thin poster surfaces should bypass the 3D-superpoint requirement. Keep source components that are geometrically disconnected but supported by the same tracked instance; blanket “largest component only” deletes chair legs and frame parts.

Open3D `RaycastingScene.cast_rays` returns nearest-hit triangle IDs, barycentric coordinates and normals; `compute_closest_points` supports controlled correspondence transfer after remeshing. This makes source ownership implementable without a new segmentation runtime. It does not create semantic IDs automatically. [Open3D raycasting API](https://www.open3d.org/docs/release/python_api/open3d.t.geometry.RaycastingScene.html)

### CDIS interface and defaults that must not be copied blindly

CDIS's documented cached interface uses RGB/depth/pose/intrinsic directories, scene PLY, `*.segs.json` superpoints, and **16-bit PNG instance-label maps**. Its adapter can consume SAM-derived label maps without loading CropFormer when `data_all_ready=true`; overlapping/nested SAM proposals must first be resolved into a consistent single-label map, while the original independent masks remain cached. GT files are evaluation inputs, not required for inference. [Author data contract](https://github.com/teamROBI/CDIS/blob/main/docs/DATA.md)

The shipped config is benchmark-specific: `voxel_size=0.03`, `queue_size=5`, depth visibility tolerance `0.05` m, `dbscan_cleanup=true`, and `grow_unassigned=true` with `grow_radius=0.03`. It also defaults `warp_z_filter`, `warp_zbuffer`, and `match_one_to_one` to false. Its debug `developing` mode truncates a scene to its first 200 frames. These facts matter for a 296-view scan. **Do not adopt these defaults unchanged:** 3 cm cleanup/growth can lose thin legs or bleed into walls/floors; missing visibility/assignment protections need explicit validation. Defaults are not evidence that those behaviors are appropriate for ReSpace. [Exact configuration](https://github.com/teamROBI/CDIS/blob/main/configs/scannet200.yaml)

The strongest transferable CDIS idea is the separation of local tracking and global geometry consolidation, not its numerical thresholds. Since its superpoints are indivisible, over-segment finely and preserve decor as independent planar assets. [CDIS data/granularity discussion](https://github.com/teamROBI/CDIS/blob/main/docs/DATA.md)

## From instance labels to actual separate meshes

Use labels to **cut and preserve geometry**, then construct assets:

- Extract observed source/refined triangles per durable object ID into an object-local coordinate frame; preserve rigid transforms, dimensions and UVs. Split boundary triangles where necessary and duplicate boundary/UV-seam vertices. Do not crop a whole bounding box or nonuniformly scale a generic substitute.
- Keep a separate architectural shell; remove every extracted object's old triangles from it. Uncertain movable fragments cannot silently become permanent wall geometry in a scene declared complete.
- Optionally refit each object with **masked RGB-D TSDF integration** if source mesh fragmentation warrants it. For an object, integrate only pixels confidently assigned to it. Outside-mask/depth-boundary pixels are invalid/unknown, not rays that carve the object away. Use object-appropriate voxel resolution and retain thin measured detail that coarse fusion would erase.
- Project/rebake high-resolution photographs into per-owner UV textures. Exclude other objects from texture samples. The current fallback's one averaged color per face cannot preserve poster text or painting detail. Masked geometry alone does not prevent the old sofa image being baked into the wall behind it.
- Complete unseen object sides and exposed room backgrounds in a **separate** constrained/generated stage, keeping observed triangles/texture pixels fixed and provenance internal. Segmentation scores do not certify those additions as measured.
- Export each entity mesh/material/texture set and a manifest linking identity, transform, source correspondence, support and provenance. A combined viewer mesh can be derived, but separately exportable assets and the manifest remain authoritative. Validate appearance, geometry, navigation and detachability before publishing the final room.

Existing local code supports parts of this: `scene.py` defines per-entity assets, owned materials, supports and `move_ready`/bundle `ready`; `pipeline.py` currently fuses/refines a combined mesh. In the inspected workspace, untracked `astra.py` generates bounded missing-triangle descriptions; it is not segmentation or per-face ownership and cannot replace the preservation stages above. ## Wall decor is a separate necessary path

Posters and board writing may lie on the same depth plane as the wall; pure geometry clustering cannot reliably split them. RoomPlan does not enumerate poster/painting/whiteboard object categories. Use image boundaries/masks plus calibrated wall-plane intersection, then cross-view wall-local polygon/appearance agreement. Do not require a separate depth ridge as a discovery criterion. [Apple categories](https://developer.apple.com/documentation/roomplan/capturedroom/object/category-swift.enum)

Rectify accepted source pixels to a metric-aspect-ratio canonical texture using homography/`warpPerspective`; create a separate thin front plane/frame/tray entity. Select the sharpest consistent observed evidence for text, not an averaged blurry mosaic or OCR retyping. Preserve source art/content exactly as supported by resolution. Content masks/materials are separate from wall paint; clean the wall atlas beneath the object and maintain a positive inward-normal separation to prevent coplanar flicker. Move the whole entity to a valid supporting wall with scale fixed. Rectification changes projection, not semantic content, and cannot reconstruct unreadable small print. [OpenCV planar homography](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html), [detailed ReSpace decor contract](EDITABLE_SCENE_RESEARCH.md#9-preserve-actual-posters-paintings-and-whiteboards)

## Failure policy and acceptance evidence

**Missing model, invalid masks, insufficient depth association or failed completion is a failed capability/stage, never a successful rectangle/proxy result.** Keep immutable inputs and internal diagnostics, but publish only a finished validated model. Bounded automatic alternate-view/reprompt attempts are allowed within budget; after failure request rescan. Do not introduce a cleanup UI, quietly delete missing small objects, or count all nine RoomPlan boxes as reconstructed objects.

Required evidence for the current scan:

| Risk | Concrete acceptance check |
|---|---|
| Actual image segmentation | Save model/checkpoint/source hashes and a source-aligned binary mask on a real frame. Mask must follow object silhouette and have meaningful foreground; detector boxes are visibly distinct from mask evidence |
| Repeated objects | Annotate a few views containing multiple chairs or repeated posters. Require distinct stable IDs through occlusion/re-entry, with no many-to-one merge merely because appearance matches |
| Thin legs/frames | Inspect the original, fused, extracted and exported geometry side by side; retain measured disconnected components supported by mask tracks. Record visible-leg coverage and floor leakage; largest-component cleanup is not an acceptable default |
| Touching objects | Test chair/table, sofa/wall and frame/wall boundaries. Moving one object must not pull neighboring geometry or leave an old duplicate behind |
| Posters/paintings/whiteboards | Preserve source pixels and aspect ratio at frontal/oblique views, no mirrored/cropped text, no wall-paint edits affecting content; moving decor exposes a clean continuous background |
| Multi-view geometry | Use withheld views and sensor-depth residuals, not only views that generated masks. Check source-surface coverage and conflicting ownership; report unobserved areas separately in internal provenance |
| Exportable assets | Remove one entity from the assembled scene and render from several viewpoints. Its source geometry disappears exactly once; exported mesh/MTL/textures resolve without external dependencies and reopen at the same metric pose |
| Completion | Observed detail remains unchanged; object backs and exposed wall/floor are coherent in all tested views. No generator-created opening blockage or invented observed artwork |
| Performance | Record embeddings/proposals/association/fusion/texture/completion times separately, actual CPU/MPS backend and peak memory, retries and billed services. Demonstrate the accepted $5/room and 30-minute envelope before promising it |

Use manually checked masks/instance correspondences on a small fixed evaluation subset as an **engineering benchmark**, not a product cleanup step. Report mask IoU/boundary errors, identity switches, cross-object leakage and observed-surface retention. Establish numerical cutoffs from the chosen sample instead of claiming an upstream ScanNet score certifies a room. The gating question is whether the original objects and decor survive independent export and movement without corrupting neighboring surfaces.

## Concrete inventory detector: HF Grounding DINO tiny on CPU

Follow-up source verification, October 17, 2026. **Choose `IDEA-Research/grounding-dino-tiny` through the existing isolated `transformers==4.46.3`/`torch==2.5.1` environment** as the next automatic proposal stage before SAM 2. The official model card is public, marked Apache-2.0, and explicitly demonstrates CUDA-or-CPU selection. No gated SAM 3 access or separately compiled original GroundingDINO package is needed for the Hugging Face implementation. This is a source-supported CPU path, not a successful inference or throughput measurement on this Mac. [Official model card](https://huggingface.co/IDEA-Research/grounding-dino-tiny), [versioned Transformers documentation](https://huggingface.co/docs/transformers/v4.46.3/model_doc/grounding-dino)

Pin **HF revision `a2bb814dd30d776dcf7e30523b00659f4f141c71`**. Files for an offline snapshot are `config.json`, `preprocessor_config.json`, `tokenizer.json`, `tokenizer_config.json`, `special_tokens_map.json`, `added_tokens.json`, `vocab.txt`, `model.safetensors`, and `README.md` for metadata/license provenance. Exclude the duplicate `pytorch_model.bin`. The safetensors weight file is listed as 689 MB with SHA-256 **`1a2412ef99bd74bcd3c2a246fa1e48581f8889a1300c9051974741314fc042f3`**; verify the actual downloaded bytes rather than hashing an LFS/Xet pointer. This research fetched metadata only, not weights. [Pinned file inventory](https://huggingface.co/IDEA-Research/grounding-dino-tiny/tree/a2bb814dd30d776dcf7e30523b00659f4f141c71), [weight metadata/hash](https://huggingface.co/IDEA-Research/grounding-dino-tiny/blob/a2bb814dd30d776dcf7e30523b00659f4f141c71/model.safetensors)

Implementation call pattern below is **not executed**. Once prefetched, use the local snapshot directory and `local_files_only=True` in place of online loading to enforce offline worker execution:

```python
import torch
from transformers import AutoProcessor, AutoModelForZeroShotObjectDetection

repo = "IDEA-Research/grounding-dino-tiny"
revision = "a2bb814dd30d776dcf7e30523b00659f4f141c71"
processor = AutoProcessor.from_pretrained(repo, revision=revision)
detector = AutoModelForZeroShotObjectDetection.from_pretrained(
    repo, revision=revision, use_safetensors=True,
    disable_custom_kernels=True,
).to("cpu").eval()
caption = "chair. table. sofa. lamp. plant. poster. painting. whiteboard."
batch = processor(images=pil_rgb, text=caption, return_tensors="pt").to("cpu")
with torch.inference_mode():
    prediction = detector(**batch)
found = processor.post_process_grounded_object_detection(
    prediction, batch.input_ids,
    box_threshold=0.30, text_threshold=0.25,
    target_sizes=[(pil_rgb.height, pil_rgb.width)],
)[0]
```

In **v4.46.3**, the postprocessor signature uses `box_threshold` and `text_threshold`, both defaulting to `0.25`; it returns `boxes`, `scores`, and phrase-string `labels`. Supplied `(height, width)` target sizes produce **pixel XYXY boxes already**: pass these to SAM 2 without another center/width conversion or scaling. The example's `0.30/0.25` is a proposed recall-oriented starting point, not a calibrated acceptance threshold. Use `post_process_grounded_object_detection`, not generic `post_process_object_detection` whose numeric labels are unsuitable as the intended semantic classes. [Exact 4.46.3 processor source](https://github.com/huggingface/transformers/blob/v4.46.3/src/transformers/models/grounding_dino/processing_grounding_dino.py)

For CPU execution, `disable_custom_kernels=True` selects the pure PyTorch deformable-attention implementation. The versioned source only attempts loading/compiling CUDA kernels when CUDA and ninja are available; the Mac CPU path does not need NVCC. On CUDA-capable machines the constructor may still attempt loading kernels independently of that flag, although the flag forces the forward fallback. Keep float32 and explicit CPU placement; avoid automatic device mapping, quantization and a new compilation stack for this first test. No `trust_remote_code` or `accelerate`-based `device_map` is required. [Versioned model implementation](https://github.com/huggingface/transformers/blob/v4.46.3/src/transformers/models/grounding_dino/modeling_grounding_dino.py)

Hard limits and integration rules:

- Use lowercase **period-separated** nouns/phrases with a final period. Keep prompt groups short: the configuration's maximum text length is 256 tokens and the model truncates overlong input. Add small-decor vocabulary in a dedicated pass rather than assuming the nine RoomPlan seeds cover it. Phrase labels can be partial/combined; retain original phrases and normalize conservatively rather than treating their string position as a class ID. [Versioned usage tips](https://huggingface.co/docs/transformers/v4.46.3/model_doc/grounding-dino), [configuration/text limit](https://github.com/huggingface/transformers/blob/v4.46.3/src/transformers/models/grounding_dino/configuration_grounding_dino.py)
- The detector proposes **2D boxes**; it supplies no masks, persistent identities, depth or dimensions. SAM 2 must segment each accepted proposal. Dedupe overlapping synonym proposals conservatively, then verify real-object depth/wall support and multiview ownership. A chair depicted in a poster is a predictable false-positive case requiring scene geometry checks.
- Run on diverse sharp views first, cache proposals by source-image/model/prompt hashes, and add views adaptively. Tiny is about 0.2B parameters, so CPU operation is not evidence that all 296 frames fit the 30-minute budget. Low-resolution/glare-obscured art remains a rescan case, and a detection missing in one view is not proof the object is absent.
- The reported current six instances with two-view 3D support are a quality signal to investigate. Extra detector boxes do not fix calibration/depth errors or justify promoting all 22 SAM masks to complete objects. Require silhouette and independent-view geometry checks before `move_ready`.
- Prefer this direct public detector for the next test over gated/CUDA-oriented SAM 3 or CLIP-ranking arbitrary automatic SAM masks. CLIP ranking does not itself supply a reliable new object proposal; neither alternative removes the need for geometry association and source-content preservation. No Gemini step is added.
